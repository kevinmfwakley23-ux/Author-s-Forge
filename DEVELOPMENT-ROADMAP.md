# Author's Forge — Development Roadmap

## Phase 0 — Foundation

Establish the application shell, project model, persistent storage, portable project package, local startup, recovery, and basic project lifecycle verification.

## Phase 1 — Book Intelligence Foundation

Establish the book genome: project identity, story premise, structure, canon, characters, locations, timeline, themes, style requirements, series continuity, and durable memory/retrieval.

## Phase 2 — Manuscript Engine

Build planning, drafting, chapter workflow, revision, scene-level control, long-form generation, context assembly, and anti-drift verification.

## Phase 3 — Research and Knowledge

Build governed web research, source capture, citation/reference records, real-world location research, historical research, niche subject research, and reusable project knowledge.

## Phase 4 — Editing and Quality

Build developmental editing, line editing, copy editing, continuity audits, factual consistency checks, style consistency checks, pacing analysis, and final manuscript quality gates.

## Phase 5 — Visual Studio

Build character visual identity, illustration references, era/location visual guidance, illustration generation workflows, image modification workflows, cover design, and reusable visual canon.

## Phase 6 — Publishing

Build formatting, front/back matter, manuscript validation, export formats, metadata, print/digital preparation, and publishing-readiness checks.

## Phase 7 — Marketing

Build book descriptions, advertising copy, social content, launch plans, author/series branding, audience positioning, and reusable marketing assets.

## Phase 8 — Advanced Productization

Add collaboration, external backup providers, user project import/export, account-level project management, marketplace-ready packaging, and production hardening.

## Phase 9 — K.I.N.G.S. Integration

Progressively delegate bounded Forge missions to K.I.N.G.S. as its autonomous engineering capabilities mature. Preserve explicit governance, verification, recovery, and human approval boundaries.

## Delivery Rule

Each mission must finish with a verifiable artifact, tests, and a durable checkpoint. A failed mission is repaired or resumed from its checkpoint before the next dependent mission begins.
