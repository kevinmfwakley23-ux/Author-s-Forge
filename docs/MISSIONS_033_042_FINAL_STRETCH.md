# Author's Forge Missions 033–042 — Final Product Directive

## Mission 033 — K.I.N.G.S. Relationship
Forge has an explicit capability-gap contract. Forge requests escalation; K.I.N.G.S. is represented as the capability escalation authority and gateway for research, planning, building, testing, and verification. Completion is recorded as attributable project state rather than hidden chat behavior.

## Mission 034 — Security and Ownership
Projects are isolated by project ID. Security policy defaults to local-first operation, explicit permissions, research consent, image-processing consent, provider disclosure, and no external uploads by default. Security actions are attributable through an audit record. Export and delete are represented by explicit permissions rather than implicit provider behavior.

## Mission 035 — Accessibility and Platforms
The platform contract explicitly covers Android, iPhone/iPad, Windows, macOS, Linux, and Web. Input/accessibility contracts cover keyboard, mouse, touch, voice, screen readers, large text, and high contrast. The underlying project model remains platform-neutral.

## Mission 036 — Voice as First-Class Input
Voice input preserves the original transcription and records a structured intent. Supported intent classes cover idea capture, story planning, editing commands, research requests, character creation, scene direction, and revision instructions. Provider-specific speech-to-text is an adapter concern; the core does not fabricate a transcription provider.

## Mission 037 — Creative Safety / IP Boundaries
Content provenance distinguishes author-owned, uploaded, generated, public-domain, external-research, third-party-reference, and unknown material. Uploaded/reference content requires explicit consent before processing. External research must identify its source. Provenance is retained with project state.

## Mission 038 — Ultimate User Experience
The architecture treats Forge as a publishing studio rather than a chat-only product. The project boundary is the durable workspace for manuscripts, canon, characters, world information, research, art, covers, marketing, metadata, decisions, and publishing state.

## Mission 039 — Golden Rules
The final product boundary preserves author authority, uncertainty signaling, observable autonomous actions, reversibility through existing version controls, and attributable project/task/artifact/decision state. Canon changes are designed to flow through the Book Genome impact mechanism instead of being treated as isolated text edits.

## Mission 040 — Book Genome
The Book Genome is a machine-readable graph containing premise, theme, genre, voice, characters, relationships, locations, timeline, events, scenes, objects, clues, reveals, conflicts, motivations, research, visual identities, art, cover, metadata, and publishing state. Graph impact analysis identifies downstream nodes and components affected by a changed node.

## Mission 041 — Final Product Standard
The product lifecycle is represented from concept through architecture, canon, characters, timeline, research, manuscript, editing, illustrations, cover, formatting, metadata, positioning, marketing, publishing, and archive. Final readiness is false until every required stage is completed.

## Mission 042 — Private Release Strategy
The repository remains structured for a private-first release. Core priority is durable project memory, canon/continuity, writing/editing, research, visual continuity, KDP preparation, production, portability/recovery, and publishing/marketing readiness. Multi-user billing and public distribution are not prerequisites for the private product architecture.

## Verification
Missions 033–042 are implemented and awaiting complete Linux verification. The complete acceptance suite must pass before these missions are considered verified. No acceptance test should be weakened merely to obtain a green result.
